# AI 小镇 V3 总任务清单（todo）

## 0. 目标与边界

本清单整合自：

- `town/ai_design.md`
- `town/rework_todo.md`

总目标：

- 在尽量保留现有 `/town` 页面骨架的前提下，实现 `OpenClaw` 配置与运行时状态驱动的可视化协作观测页。

状态说明：

- `[x]` 已完成
- `[ ]` 待完成
- `[ ! ]` 当前环境不可验证或被外部依赖阻塞

边界约束（必须满足）：

- 单办公室场景（不做多办公室地图）
- 多主任务并行时在同一办公室分区展示
- 办公室成员池是全局共享状态
- `OpenClaw(main)` 是唯一主控视觉角色
- 同一 Agent 可多任务分身并行
- 回放按单个 run，最多 2000 事件，进入回放冻结实时视图
- 右侧栏收敛为按钮入口，复杂内容使用弹窗/抽屉
- 键盘移动仅作用于当前选中的展示小人，位置仅本地可见

## 3. 总任务清单

## 3.1 后端：Town 聚合与桥接

- [x] T-001 新增 `GET /api/town/snapshot` 聚合接口  
  描述：聚合 `openclaw/agents`、`system/skills`、`sessions`、`events`、办公室成员池，返回 Town 单次渲染快照。  
  验收：前端只请求 snapshot 即可拿到主镇、办公室、运行态基础信息。

- [x] T-002 新增 `PUT /api/town/office-members`  
  描述：维护全局共享办公室成员池（手动选中/取消、自动拉入标记）。  
  验收：A 管理员修改后，B 管理员刷新可见同样成员池。

- [x] T-003 新增 `POST /api/town/runs`（Town 专用桥接）  
  描述：接收办公室任务输入，桥接到 OpenClaw 实际入口，并记录 run 与 session 映射。  
  验收：点击“开始协作”后产生真实 run，且能追踪到后续 session 事件。

- [x] T-004 新增 `GET /api/town/runs/:id/logs`  
  描述：返回单 run 的高层级时间线（主任务、参与 Agent、关键事件、完成/失败）。  
  验收：日志弹窗在不读原始底层日志文件的情况下可展示 run 时间线。

- [x] T-005 新增 `POST /api/town/agents/:id/reset`  
  描述：提供会话急救入口（清理异常 session、解除忙碌、可选重置运行态）。  
  验收：异常 Agent 可从“卡死”状态恢复到办公室待命或主镇状态。

## 3.2 后端：事件归一化与状态映射

- [x] T-010 定义 Town 事件规范  
  描述：统一事件类型、字段和 payload（必须含 `time/runId/agentId/sessionId/type`）。  
  验收：同类事件字段稳定，不依赖文案解析。

- [x] T-011 接入/扩展事件流  
  描述：将 OpenClaw 关键行为归一化到 `/api/events` + ws 推送（run started/completed, session spawned, agent busy/idle, im received）。  
  验收：Town 可仅靠事件 + snapshot 推进实时状态。

- [x] T-012 第一阶段近似判定实现  
  描述：使用“事件 + session 最近更新时间”推断忙碌/完成/最近活跃。  
  验收：状态不会长时间卡死，且文案明确为近似同步。

## 4. 完成定义（DoD）

全部任务完成后，必须同时满足：

- `AI 小镇` 主要数据来自真实 OpenClaw 配置与运行态
- 单办公室内支持多主任务分区并行
- 同 Agent 多分身并行可视化可用
- 回放模式可复盘单 run 且不污染实时态
- 轻量编辑、skills 开关、session 清理可在 Town 内完成
- 协作权限摘要可视化可用
- 键盘移动仅影响本地展示，不影响真实协作状态
- 页面仍保持“观测优先、可玩增强”的定位，不回退为玩法主导页面

## 7. 最终验收门槛

以下任一项不满足，均不视为完成：

- 主路径仍依赖前端 mock run 流程。
- 办公室并行任务不是分区表达，或超过 6 区没有溢出策略。
- 回放不是单 run，或回放期间未冻结实时视图。
- 同一 Agent 无法并行分身，或热力图阈值不一致。
- 键盘移动影响了全局共享状态。
- 轻量编辑/skills/session 清理无法在 Town 内完成。
