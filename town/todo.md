# AI 小镇升级版执行任务清单

## 0. 文档目的

本文根据 [design_report.md](/Users/lizhongxuan/Desktop/ClawPanel/town/design_report.md) 生成，目标不是罗列想法，而是给出一份可直接排期、分工、验收、回滚的执行清单。

本清单有 4 个原则：

- 先解决高风险，再做高观感
- 先冻结契约，再写代码
- 先保证 Town 仍是观测皮肤，再增强可视化和推荐
- 对不确定但影响大的事项，先设“决策闸门”，不直接开工

## 0.1 状态标记

- `[ ]` 未开始
- `[~]` 进行中
- `[x]` 已完成
- `[!]` 需先拍板或被外部依赖阻塞

## 0.2 执行边界

- 不破坏 `/town` 双场景结构
- 不破坏 `snapshot` 作为主渲染数据源的原则
- 不把 Town 变成新的 Agent 运行时
- 不在没有真实上游数据的情况下伪造真实调度结果
- 命令、prompt、LLM 原文允许直接显示到 UI/WS，但必须记录这是一项显式接受的高风险决策

## 0.3 当前执行前提

以下前提已经拍板，本清单按此推进：

- 当前项目按完整版本开发，不再按 `MVP / Beta` 切阶段承诺
- 执行顺序仍坚持“先基础底座与安全，再调度观测与体验，再治理与扩展”
- 正式接口冻结默认采用：
  - `GET /api/town/runs/:id/replay`
  - `GET /api/town/runs/:id/details`
  - 不单独拆 `/plan` 与 `/topology`，除非性能压测证明有必要
- 对 `plan / 调度理由 / topology / command / skill` 只接受真实上游数据
  - 若 OpenClaw 未提供，则 UI 直接显示“暂无数据/上游未提供”
  - 不允许 Town 做近似推断
- 命令、prompt、LLM 原文默认直接显示
  - 不做脱敏
  - 不做语义摘要改写
  - 如因布局需要，仅允许折叠、换行或长度裁剪，不改变原文语义
- 当前默认使用场景是受信管理端环境
  - 若后续开放给普通用户或外部租户，必须重开这项决策
- 实时聊天水泡默认采用：
  - WS `town.actor.bubble` 为主
  - `snapshot.liveActions` 仅作断线恢复兜底

## 7. 已确认事项

以下事项已拍板，并应作为后续实现边界：

1. 当前项目直接按完整版本开发，不再按 `MVP / Beta` 切阶段承诺。
2. 正式接口默认收敛为 `/replay + /details`，不额外拆 `/plan` 与 `/topology`。
3. `plan / 理由 / topology / command / skill` 不接受近似推断；没有真实上游数据就直接显示“暂无数据/上游未提供”。
4. 命令、prompt、LLM 原文直接显示，不处理敏感内容；此决定对应的高风险在文档中保留记录。

这版 `todo.md` 的核心不是“把功能列出来”，而是确保：

Town 的升级先做成 **稳定、可回滚、可观测、可解释**，再做成 **更炫、更会推荐、更可扩展**。
