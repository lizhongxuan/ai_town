# AI 小镇逻辑修正设计文档

> 日期: 2025-03-17
> 背景: 当前 Town 的"办公室/主镇"区分是纯 UI 概念，对 OpenClaw 调度没有实际影响。本文档定义一套修正方案，让办公室成员选择真正影响任务调度行为。

## 1. 核心原则

- Town 仍是观测皮肤，不做调度决策
- 调度智能全部交给 openclaw-main（managerAgentID）
- Agent 数据唯一来源：`~/.openclaw/openclaw.json`
- 办公室成员持久化：`OFFICE.md`（人可读可编辑）
- 两种任务模式有明确不同的语义

## 2. Agent 数据源统一

### 现状问题

`loadAgentIDs` 有两条路径：
1. 读 `openclaw.json` 的 `agents.list`
2. 扫描 `~/.openclaw/agents/` 目录

两者合并去重，导致可能出现"幽灵 Agent"（磁盘有目录但配置里没有）。

### 修正方案

- Agent 列表只从 `openclaw.json` 的 `agents.list` 读取
- 删除磁盘目录扫描逻辑（`collectAgentIDsFromConfigAndDisk` 中扫描 `agents/` 目录的部分）
- `agents.list` 为空时，降级为单 Agent 模式（只有 `main`）
- Snapshot 构建时检测 `openclaw.json` 的 `ModTime`，变化时自动清除缓存

### 涉及文件

- `internal/handler/agents_helper.go`
  - `loadAgentIDs()`: 去掉磁盘扫描分支，只走 `collectAgentIDsFromList`
  - `collectAgentIDsFromConfigAndDisk()`: 去掉 `os.ReadDir(agentsDir)` 扫描
- `internal/handler/town.go`
  - `buildTownSnapshotFromStore()`: 增加 `openclaw.json` ModTime 检测，变化时清缓存

## 3. Agent 位置状态机

### 状态定义

```
┌─────────┐     手选加入OFFICE.md      ┌──────────────┐
│  主镇    │ ──────────────────────────→ │  办公室(闲逛) │
│ mainTown │ ←────────────────────────── │  office_idle  │
└─────────┘     从OFFICE.md移除         └──────────────┘
     │                                        │
     │ IM任务/被调度器选中                      │ 办公室任务/被调度器选中
     ↓                                        ↓
┌──────────────┐                        ┌──────────────┐
│  办公室(工位) │                        │  办公室(工位) │
│ office_busy  │                        │ office_busy  │
└──────────────┘                        └──────────────┘
     │                                        │
     │ 任务结束                                │ 任务结束
     ↓                                        ↓
  不在OFFICE.md → 回主镇              在OFFICE.md → 回办公室闲逛
```

### 位置判定规则

```
if agent 正在执行任务:
    location = "office_busy"（工位上工作）
else if agent.id in OFFICE.md:
    location = "office_idle"（办公室闲逛）
else:
    location = "mainTown"（主镇闲逛）
```

## 4. OFFICE.md 持久化

### 文件位置

`{dataDir}/town/OFFICE.md`

### 文件格式

```markdown
# 办公室成员

> 此文件记录被手动选入办公室的 Agent。
> 可直接编辑此文件，每行一个 Agent ID。
> 不在此文件中的 Agent 默认在主镇。

- researcher
- coder
- writer
```

### 读写逻辑

- 读取：解析每行 `- xxx` 格式，提取 Agent ID，去重
- 写入：用户通过 UI 选人时，重写整个文件
- 校验：写入前检查 Agent ID 是否存在于 `openclaw.json`，不存在的跳过
- 并发：文件级 `sync.Mutex` 保护读写

### 与现有 DB 表的关系

- `town_office_member` 表不再作为办公室成员的权威来源
- 该表可保留用于记录历史/审计，但 snapshot 构建时只读 OFFICE.md
- 迁移：首次启动时，如果 OFFICE.md 不存在但 `town_office_member` 有数据，自动生成 OFFICE.md

### 涉及文件

- 新增 `internal/handler/town_office.go`
  - `ReadOfficeMembers(cfg) → []string`
  - `WriteOfficeMembers(cfg, []string) → error`
  - `IsOfficeMember(cfg, agentID) → bool`
- `internal/handler/town.go`
  - `UpdateTownOfficeMembers`: 改为读写 OFFICE.md
  - `buildTownSnapshotFromState`: location 判定改用新规则

## 5. 两种任务模式

### 模式 A：IM 任务（被动触发）

```
用户通过 IM 发消息 → OpenClaw 网关接收
→ openclaw-main 自己决定调度谁
→ Town 通过 bridge 结果观测到参与者
→ 参与的 Agent 临时显示在办公室工位
→ 任务结束 → 不在 OFFICE.md 的回主镇，在 OFFICE.md 的回办公室闲逛
```

改动：
- `CreateTownRun(source="im")`: 不再传 `standbyAgents`，让 openclaw-main 自己选
- 去掉 `applyTownAutoAdded` 逻辑（不再永久加入办公室）
- `finalizeTownRun`: 任务完成后按 OFFICE.md 归位

### 模式 B：办公室任务（主动发起）

```
用户在办公室 UI 发任务
→ 读取 OFFICE.md 中的全部 Agent 作为 standbyAgents
→ 连同问题一起传给 openclaw-main
→ openclaw-main 从 standbyAgents 中选人、决定串行/并行
→ 被选中的 Agent 显示在工位上工作
→ 未被选中的 Agent 继续在办公室闲逛
→ 任务结束 → 按 OFFICE.md 归位
```

改动：
- `CreateTownRun(source="office")`: 自动读取 OFFICE.md 作为 `standbyAgents`
- Bridge 调用时确保 standbyAgents 真正传给 OpenClaw

### Bridge 调用改动

#### 本地模式（当前问题最大）

现在：
```go
command := exec.CommandContext(ctx, bin, "agent", "--agent", req.ManagerAgentID, "--message", req.Prompt, "--json")
```

改为：
```go
args := []string{"agent", "--agent", req.ManagerAgentID, "--message", req.Prompt, "--json"}
if len(req.StandbyAgentIDs) > 0 {
    args = append(args, "--agents", strings.Join(req.StandbyAgentIDs, ","))
}
command := exec.CommandContext(ctx, bin, args...)
```

> 前提：OpenClaw CLI 需要支持 `--agents` 参数来限定调度范围。
> 如果 OpenClaw CLI 暂不支持，则先通过 prompt 注入方式传递：
> 在 prompt 前面拼接 "可用协作 Agent: researcher, coder, writer\n\n" + 原始 prompt

#### HTTP 模式

已经在传 `standbyAgents`，无需改动。

### 涉及文件

- `internal/handler/town.go`
  - `CreateTownRun`: 区分 source="im" 和 source="office"
  - `finalizeTownRun`: 任务完成后按 OFFICE.md 归位
  - `dispatchTownRunBridgeLocal`: 传 standbyAgents
- `internal/handler/town_schema.go`
  - `townCreateRunRequest`: source 增加 "office" 枚举

## 6. 任务结束归位逻辑

### 触发时机

`finalizeTownRun` 中任务状态变为 `completed` 或 `error` 时。

### 归位规则

```go
officeMembers := ReadOfficeMembers(cfg)
officeSet := toSet(officeMembers)

for _, agentID := range participantAgentIDs {
    if officeSet[agentID] {
        // 在 OFFICE.md → 回办公室闲逛
        instance.Status = "idle"
        // 保留 instance 但 location = "office_idle"
    } else {
        // 不在 OFFICE.md → 回主镇
        // 删除 instance，agent 自然回到 mainTown
    }
}
```

### 涉及文件

- `internal/handler/town.go`
  - `finalizeTownRun`: 增加归位逻辑
  - 错误路径也需要归位（bridge 失败、超时等）

## 7. openclaw.json 变更检测

### 方案

在 snapshot 缓存逻辑中增加文件 ModTime 检查：

```go
var townConfigModTime time.Time

func buildTownSnapshotFromStore(cfg *config.Config) (TownSnapshot, error) {
    // 检查 openclaw.json 是否变化
    configPath := filepath.Join(cfg.OpenClawDir, "openclaw.json")
    if info, err := os.Stat(configPath); err == nil {
        if info.ModTime().After(townConfigModTime) {
            townConfigModTime = info.ModTime()
            InvalidateTownSnapshotCache()
        }
    }
    // ... 原有缓存逻辑
}
```

### 涉及文件

- `internal/handler/town.go`
  - `buildTownSnapshotFromStore`: 增加 ModTime 检测

## 8. 执行顺序

| 步骤 | 内容 | 难度 |
|------|------|------|
| F-01 | Agent 数据源统一（只读 openclaw.json） | 小 |
| F-02 | openclaw.json 变更检测 | 小 |
| F-03 | OFFICE.md 读写模块 | 小 |
| F-04 | Agent 位置状态机（snapshot 构建改用新规则） | 中 |
| F-05 | 去掉 auto_added 永久写入 | 小 |
| F-06 | 任务模式区分（IM vs 办公室） | 中 |
| F-07 | Bridge 调用传 standbyAgents | 小 |
| F-08 | 任务结束归位逻辑 | 中 |

建议按 F-01 → F-02 → F-03 → F-04 → F-05 → F-06 → F-07 → F-08 顺序执行。

## 9. 不改的部分

- OpenClaw 的调度逻辑（Town 不参与）
- 现有 WS 双通道（invalidate + bubble）
- 现有 snapshot 契约结构（只改 location 字段的取值逻辑）
- 现有 run/log/event 数据模型
- 前端组件结构（只需适配新的 location 值）

## 10. 风险点

1. OpenClaw CLI 是否支持 `--agents` 参数限定调度范围？如果不支持，需要用 prompt 注入方式传递，效果不可控
2. OFFICE.md 文件被外部编辑器改坏（格式错误）→ 需要容错解析
3. 任务执行中 OFFICE.md 被修改 → 归位时以任务结束时的 OFFICE.md 为准，不回溯
4. openclaw.json 高频修改导致缓存频繁失效 → ModTime 检测已经足够轻量，不是问题
